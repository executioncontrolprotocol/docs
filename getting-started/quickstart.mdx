This path uses the **published CLI** only. You do not need to clone the repository.

You will install the CLI, create a local system config, point the OpenAI provider at a key (or use Ollama), download a tiny sample manifest, then **validate** and **run** it.

## Before you begin

- Install [Node.js](https://nodejs.org/) (use the current **LTS** release).
- Pick **one** model backend:
  - **OpenAI:** you need an API key.
  - **Ollama:** install [Ollama](https://ollama.com/) and keep it running locally (no API key).

## 1. Install the CLI

```bash
npm install -g @executioncontrolprotocol/cli
```

Check that `ecp` is on your `PATH`:

```bash
ecp --help
```

## 2. Create a project folder and init config

```bash
mkdir ecp-demo && cd ecp-demo
ecp config init
```

That writes **`ecp.config.yaml`** in the current directory with conservative defaults (built-in OpenAI and Ollama entries and matching allow lists). To install config in your home directory instead, use `ecp config init --global`.

If a config file already exists, either edit it or run `ecp config init --force` to replace it.

## 3. Provide secrets (OpenAI) or pull a model (Ollama)

<Tabs>
  <Tab title="OpenAI">
    Set your API key in the environment for this shell session:

    ```bash
    export OPENAI_API_KEY="sk-..."
    ```

    On Windows (PowerShell):

    ```powershell
    $env:OPENAI_API_KEY = "sk-..."
    ```

    The OpenAI provider reads **`OPENAI_API_KEY`** when the key is not set in config. For keychains, `.env` files, and other stores, see [Security](/learn/security) and run `ecp config secrets --help`.
  </Tab>
  <Tab title="Ollama">
    Pull a small model that matches the sample manifest (names may vary by Ollama version):

    ```bash
    ollama pull gemma3:1b
    ```

    Ensure Ollama is running (default URL `http://localhost:11434`).
  </Tab>
</Tabs>

## 4. Download a sample Context

Save the [single-executor example](https://github.com/executioncontrolprotocol/executioncontrolprotocol/blob/main/examples/single-executor/context.yaml) as **`context.yaml`** in **`ecp-demo`**.

For example, with **curl**:

```bash
curl -fsSL -o context.yaml https://raw.githubusercontent.com/executioncontrolprotocol/executioncontrolprotocol/main/examples/single-executor/context.yaml
```

Or download the file from GitHub in your browser and save it as **`context.yaml`**.

## 5. Validate

<Tabs>
  <Tab title="OpenAI">
    The sample manifest defaults to Ollama in the file, so pass the provider and model you want for this run:

    ```bash
    ecp validate context.yaml --provider openai --model gpt-4o-mini -i topic=test
    ```
  </Tab>
  <Tab title="Ollama">
    ```bash
    ecp validate context.yaml -i topic=test
    ```
  </Tab>
</Tabs>

To see required inputs without supplying values:

```bash
ecp validate context.yaml --skip-inputs
```

## 6. Run

<Tabs>
  <Tab title="OpenAI">
    ```bash
    ecp run context.yaml --provider openai --model gpt-4o-mini -i topic="Hello from ECP"
    ```
  </Tab>
  <Tab title="Ollama">
    ```bash
    ecp run context.yaml -i topic="Hello from ECP"
    ```
  </Tab>
</Tabs>

Tracing is on by default. List and open traces:

```bash
ecp trace list
ecp trace <run-id>
```

Turn tracing off for a run with **`--no-trace`**.

## Command help

The CLI is the source of truth for flags and subcommands:

```bash
ecp --help
ecp run --help
ecp validate --help
ecp config --help
```

## What you just ran

The sample Context declares **inputs**, **outputs**, **schemas**, **orchestration**, and an **executor** with **policies** (for example tool access and budgets). The system config you created controls which **providers** and **models** the host allows.

# Build from source

Use this path when you are changing ECP (Execution Control Protocol) packages, or when `@next` is not on the npm registry yet. Day-to-day usage should [install the CLI from npm](/getting-started/quickstart) once a dist-tag exists.

## Prerequisites

- Node.js 22+
- pnpm 10 (install from the **repo root**, never inside individual packages)

## Clone and build

Work from `milestone/cli-reset` during the CLI reset. Do not push `main` or `development` from that milestone (`main` publishes to npm).

```bash
git clone https://github.com/executioncontrolprotocol/executioncontrolprotocol.git
cd executioncontrolprotocol
git checkout milestone/cli-reset
pnpm install
pnpm run build
```

Link the CLI for local commands:

```bash
cd packages/cli
pnpm link --global
```

Prove a clean install from packed tarballs (core, node, plugin-sdk, CLI, and every plugin):

```bash
pnpm run test:plugin-pack
```

That smoke does not hit unpublished npm. It is the install proof until `@next` exists.

## Layout

| Path | Package |
| ---- | ------- |
| `packages/core` | `@executioncontrolprotocol/core` (Fluent API, engine, `./types`) |
| `packages/environments/node` | `@executioncontrolprotocol/node` |
| `packages/environments/browser` | `@executioncontrolprotocol/browser` |
| `packages/cli` | `@executioncontrolprotocol/cli` |
| `packages/plugin-sdk` | `@executioncontrolprotocol/plugin-sdk` |
| `packages/mcp` | `@executioncontrolprotocol/mcp` (Phase 7 rebuild) |
| `plugins/plugin-*` | First-party plugins (independent versions, Changesets pre-`next`) |

Versions for core, hosts, CLI, plugin-sdk, and plugins start at `1.0.0-next.0`. MCP stays `0.14.1` until Phase 7. In-repo dependencies use `workspace:^`, never `file:`.

Release tooling is Changesets (`pnpm exec changeset`). Prereleases, when published, use the `next` dist-tag from a milestone branch. See the monorepo `RELEASING.md`.

## Checks

```bash
pnpm run check
pnpm run test:browser
```

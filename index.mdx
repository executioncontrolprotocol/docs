ECP (Execution Control Protocol) is the **deterministic delegation** layer for agents. Your agent works out an approach once and writes it down as a JSON **execution**: which capabilities run, in what order, with which data. A local **host** validates it, runs it, and records every step. The next time the same work comes up, you run the execution again instead of prompting a model again.

MCP standardizes how a model calls one tool. ECP standardizes how an agent delegates a **graph** of capability calls: typed, checked before it runs, recorded when it runs, and repairable when it fails.

## How it works

<Steps>
  <Step title="Discover">
    `ecp retrieve --type capability --query csv` lists what installed plugins can do, with each capability's `accepts` and `returns` schemas.
  </Step>
  <Step title="Write">
    Write an `*.ecp.json` execution: steps that call capabilities, plus branches, loops, parallel lines, and transform steps.
  </Step>
  <Step title="Validate">
    `ecp execute flow.ecp.json --validate` checks structure, inputs, data flow, and types. Each issue comes with a JSON path, a code, and suggestions.
  </Step>
  <Step title="Run and inspect">
    `ecp execute flow.ecp.json` runs it on the host. The run record keeps every step's input, output, and error.
  </Step>
  <Step title="Save">
    `ecp commit` saves a working execution under an id so any agent, the App, or a script can run it again.
  </Step>
</Steps>

The same three operations, `retrieve`, `execute`, and `commit`, are available from the [CLI](/reference/cli), as [MCP tools](/guides/mcp), and over the host's local HTTP API. The [App](/guides/app) shows the same execution as a live graph.

## A first execution

```json hello.ecp.json
{
  "schema": "@executioncontrolprotocol.execution",
  "version": "2.0",
  "steps": [
    {
      "id": "greet",
      "uses": "@executioncontrolprotocol/core.transform",
      "accepts": { "type": "object", "properties": { "name": { "type": "string" } }, "required": ["name"] },
      "returns": { "type": "object", "properties": { "greeting": { "type": "string" } }, "required": ["greeting"] },
      "input": { "name": "world" },
      "script": { "lang": "js", "source": "return { greeting: `Hello, ${input.name}!` }" },
      "as": "hello"
    }
  ]
}
```

```bash
ecp execute hello.ecp.json
```

```text
greet  completed
{
  "hello": {
    "greeting": "Hello, world!"
  }
}
```

## What you work with

| Piece | What it is |
| ----- | ---------- |
| **Execution** | A JSON graph of steps (`*.ecp.json`). Portable; never contains secrets. |
| **Capability** | One typed operation a plugin provides, such as `@executioncontrolprotocol/core.transform`. |
| **Plugin** | An npm package that provides capabilities. Installed with `ecp plugins install`. |
| **Host** | A local background process that validates and runs executions. Starts on demand. |
| **Config** | Stored plugin settings. Secrets are references, resolved from your OS keychain. |
| **Run** | One run of an execution: status, result, and a record of every step. |

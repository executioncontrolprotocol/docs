ECP (Execution Control Protocol) is the **deterministic delegation** layer an agent uses when work should be repeatable, governed, and repairable. You reason about an approach once, capture it as a workflow file, and run it under policies instead of re-prompting a model every time.

MCP standardizes how models call tools. ECP standardizes how an agent **delegates** a graph of those tools: which steps run, in what order, under which plugins and policies, with a journal you can inspect and rerun.

## Determinism ladder

1. **Search** the installed capabilities (`ecp search`, `ecp describe`).
2. **Author** a single `*.ecp.ts` workflow file.
3. **Validate** (`ecp validate --json`) until the graph and bindings are sound.
4. **Run** (`ecp run --json`). On failure, read the error code and the journal.
5. **Repair** the file and `ecp runs rerun --from <step>`.

The CLI is the primary surface. A model should learn flags from `ecp --help`. [MCP](/guides/mcp) (`ecp mcp serve`) exposes the same host as tools. The visual [App](/guides/app) (`ecp app`) is the same host in a graph.

## Install

```bash
npm install -g @executioncontrolprotocol/cli
npx skills add executioncontrolprotocol/docs
```

The field-test is **0.50.0** on `latest` (not 1.0). Contributors who are changing packages can [build from source](/getting-started/build-from-source).

Then:

```bash
ecp init brief
ecp run brief.ecp.ts
```

## What you operate

| Piece | Role |
| ----- | ---- |
| **Workflow** | Portable graph (`*.ecp.ts` or JSON). Bindings compile into a separate requirements document. |
| **Environment** | Host (Node or browser) plus installed plugins and policies. |
| **Ecp** | Operational APIs after `init()`: `run`, `validate`, `describe`, `search`, `invoke`, and more. |
| **Plugin** | npm package that registers an extension or policy and generates CLI commands. |
| **Journal** | One directory per run under `.ecp/runs/<runId>/`. |

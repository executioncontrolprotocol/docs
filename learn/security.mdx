# Security

ECP (Execution Control Protocol) treats execution as a governed surface: what can run, what state can change, and where secrets live.

## Principles

- **Workflows are portable** — no API keys or host secrets in manifests
- **Environments bind policy** — budgets, approvals, state control, registry rules
- **Secrets stay on the host** — OS keychain (CLI) or browser vault (demo)

## Policies

First-party policy packages include:

| Policy | Role |
| ------ | ---- |
| Budget | Limit spend / usage |
| Approval | Gate sensitive actions |
| State control | Constrain how run state is written |
| Registry control | Authorize dynamic extension registration (`policy:pre` / registry requests) |

Bind policies on the environment builder (for example `.withPolicies([...])`) before `init()`.

## Secrets

### Node / CLI

Store values in the OS keychain:

```bash
ecp config secrets add openai/api-key
ecp config secrets list
ecp config secrets get openai/api-key
ecp config secrets remove openai/api-key
```

Ref form: `ecp://<key>` (for example `ecp://openai/api-key`).

Bind secrets into **extension config** at environment setup — not into workflow manifests:

```ts
import "@executioncontrolprotocol/secrets"
import { environment, extension, secrets } from "@executioncontrolprotocol/node"

export default (await environment("demo")).withExtensions([
  extension("@executioncontrolprotocol/secrets").with({}),
  extension("@executioncontrolprotocol/openai").with({
    apiKey: secrets("openai/api-key"),
  }),
])
```

`secrets("key")` resolves via the keychain when the environment initializes. Prefer this over hardcoding keys or inventing ad-hoc `.env` loaders for extension config.

### Browser demo

Cloud keys belong in the demo’s encrypted secrets vault when the UI prompts for them. See [Demo providers and configuration](/getting-started/browser-demo-providers) and the [hosted demo](https://executioncontrolprotocol.github.io/browser-demo/).

## Registry freeze (browser)

Browser hosts often freeze the extension registry at a lifecycle point (`environment:ready`, `environment:beforeRun`, or manual). Pair freeze with **registry-control** so late registration is an explicit, authorized path — important when pages expose `globalThis.ecp`.

## Default posture

Prefer allowlisted capabilities in the environment you ship. Validate workflows against that environment before run:

```bash
ecp validate workflow.ts --env environment.ts
ecp run workflow.ts --env environment.ts --dry-run
```

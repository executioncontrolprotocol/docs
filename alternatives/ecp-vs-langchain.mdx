---
title: "ECP vs LangChain"
description: "When to use ECP (Execution Control Protocol) instead of, or alongside, LangChain: an agent-written JSON execution versus an application framework."
---

LangChain is a **framework** for building LLM applications in code. ECP (Execution Control Protocol) is a **protocol and local host** that an agent uses to hand off repeatable work as data.

| | LangChain | ECP |
| --- | --- | --- |
| Who writes the graph | A developer, in Python or TypeScript | An agent (or a person), as a JSON execution |
| Unit of work | Chains and graphs in application code | A portable `*.ecp.json` execution |
| Checking | Your tests | Built-in validation of inputs, references, and types before the run |
| Record | Tracing products | A run record with every step's input, output, and error |
| Extending | Integrations inside the framework | npm plugins with typed capabilities |
| Interface for agents | Your app's API | `retrieve`, `execute`, `commit` over CLI, MCP, or HTTP |

Use LangChain when you are writing an application. Use ECP when an agent should capture, validate, and rerun a sequence of capability calls without you writing code for each one.

They work together: a LangChain app can call ECP over MCP or HTTP, and an ECP plugin can wrap a model provider or a chain.

# CLI

Generated from oclif manifests in the ECP checkout (`packages/cli` operations and `plugins/plugin-*/oclif.manifest.json`). Do not hand-edit. Learn flags from `ecp <command> --help` when in doubt.

Install with `npm install -g @executioncontrolprotocol/cli` (**0.50.0** on `latest`). Contributors who are changing packages can [build from source](/getting-started/build-from-source).

## `--json` envelope

Every command accepts `--json`. Success prints `{ ok: true, data }`. Failure prints `{ ok: false, error: { code, message, path, suggestions } }` and a non-zero exit (`0` success, `1` failed run, `2` usage, `3` validation, `4` plugin/environment load).

There is no `ecp test`, `ecp serve`, `ecp up`, or root `ecp encode` / `ecp decode`. Format plugins expose `ecp format-toon encode` (and similar). There is no shell-completion command; discover the surface with `ecp --help` and topic help (`ecp workflows`, `ecp environments`, `ecp config`, `ecp plugins`).

## Plugin install (oclif)

`ecp plugins install`, `ecp plugins link`, `ecp plugins uninstall`, and `ecp plugins update` come from `@oclif/plugin-plugins`. First-party packages install without a prompt. Third-party plugins require approval (`ECP_PLUGIN_DENIED` if you refuse). Source installs need `--allow-source`. `ecp plugins install <name> --add-to-env` appends a commented binding stub to the default environment file.

```bash
ecp plugins install jsonata
ecp plugins link plugins/plugin-jsonata
```

## `ecp adobe-firefly-services audio-video-cancel-render-job`

Cancel a render job

Aborts an in-flight render job. Returns `202 Accepted` as soon as the cancellation has been accepted; subsequent calls to `GET /v1/status/\{jobId}` will report `"status": "canceled"` once the worker has fully stopped the underlying render. **Applicable only to render jobs submitted via `POST /v1/templates/render`.** This endpoint does not apply to Describe, Reframe, TLS, TTS, or Avatar jobs. **Notes:** - Cancellation is idempotent. - Once propagated to the worker, in-progress outputs are not uploaded to the destinations specified in the original render request. - For a short window after the PUT, the status endpoint may still report `running`; poll until it transitions to `canceled`.

Plugin: `@executioncontrolprotocol/plugin-adobe-firefly-services`.

Aliases: `ecp firefly audio-video-cancel-render-job`.

## `ecp adobe-firefly-services audio-video-list-render-jobs`

List render jobs

Returns a paginated list of template render jobs owned by the authenticated caller, optionally filtered by status and creation date. **Applicable only to render jobs submitted via `POST /v1/templates/render`.** Jobs from other API types (Describe, Reframe, TLS, TTS, Avatar) are not returned. **Filter syntax (FIQL):** - `status==running` — single status equality - `status=in=(running,not_started)` — status set membership - `createdDate=ge=2026-05-01T00:00:00Z` — absolute ISO 8601 lower bound - `createdDate=ge=-P7D` — relative ISO 8601 duration (last 7 days) - Combine with `;` (AND): `status==running;createdDate=ge=-P7D` **Default filter:** all statuses, `createdDate` within the last 30 days. **Retention:** `createdDate` filter values must fall within the 30-day retention window. **Pagination:** follow `paging.nextUrl` until it is absent (last page).

Plugin: `@executioncontrolprotocol/plugin-adobe-firefly-services`.

## `ecp adobe-firefly-services substance3d-create-space-v2`

Create Space API

## Overview The **Substance 3D API** provides a way to upload and temporarily store files. Uploading files requires a **multipart/form-data** request to send data. The request requires a **files** field containing a list of files. Each file's **filename** field can contain a filepath to specify where the file will be stored in the space. Example for this files tree: ``` ├── textures │ ├── diffuse.png │ └── normal.png └── lighthouse.fbx ``` HTTP data relative to the previous files tree: ```HTTP POST /spaces HTTP/1.1 Host: localhost:8080 Content-Type: multipart/form-data; boundary=----WebKitFormBoundary7MA4YWxkTrZu0gW ------WebKitFormBoundary7MA4YWxkTrZu0gW Content-Disposition: form-data; name="files"; filename="lighthouse.fbx" Content-Type: model/vnd.autodesk.fbx (data) ------WebKitFormBoundary7MA4YWxkTrZu0gW Content-Disposition: form-data; name="files"; filename="textures/diffuse.png" Content-Type: image/png (data) ------WebKitFormBoundary7MA4YWxkTrZu0gW Content-Disposition: form-data; name="files"; filename="textures/normal.png" Content-Type: image/png (data) ------WebKitFormBoundary7MA4YWxkTrZu0gW-- ``` Curl command to create this file tree: ``` curl -X POST https://s3d.adobe.io/v2/spaces \ -F "files=@Local/Path/To/The/Local/File/lighthouse.fbx;filename=lighthouse.fbx" \ -F "files=@Local/Path/To/The/Local/File/diffuse.png;filename=textures/diffuse.png" \ -F "files=@Local/Path/To/The/Local/File/normal.png;filename=textures/normal.png" ``` The result of the post is a **JSON** which contained the **id** of the space created. Space **id** can be used into a space source to use space content as a source for API operations. Example of a space source: ```json \{ "space": \{ "id": "" } } ```

Plugin: `@executioncontrolprotocol/plugin-adobe-firefly-services`.

Aliases: `ecp firefly substance3d-create-space-v2`.

### Flags

| Flag | Type | Required | Description |
| --- | --- | --- | --- |
| `--json` | boolean | no | Format output as json. |
| `--input` | option | no | JSON object for the full input, from a file or stdin (`-`) |

### Examples

```bash
ecp adobe-firefly-services substance3d-create-space-v2 --input payload.json
```

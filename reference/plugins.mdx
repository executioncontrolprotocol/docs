Plugins are npm packages that add capabilities to ECP (Execution Control Protocol). The host ships with the core plugin; you install the rest as you need them.

## First-party plugins

The first-party plugins, with their source and READMEs, live in the ECP repository:

<Card title="executioncontrolprotocol/plugins" icon="github" href="https://github.com/executioncontrolprotocol/executioncontrolprotocol/tree/development/plugins">
  Browse every first-party plugin, its capabilities, and its configuration.
</Card>

The **core** plugin is bundled with the host and can't be uninstalled. It provides:

| Capability | Does |
| ---------- | ---- |
| `@executioncontrolprotocol/core.transform` | Runs a JavaScript transform in the host sandbox. See [Transforms](/guides/transforms-and-scripts). |
| `@executioncontrolprotocol/core.parse-csv` | Parses a CSV file into `columns` and `rows`. |

## Discover capabilities

The installed set is the source of truth. Ask the host instead of a list:

```bash
ecp retrieve --type capability                       # everything installed
ecp retrieve --type capability --query "image"       # search
ecp retrieve --type capability --id <capability-id>  # schemas, config, timeout
```

If an execution uses a capability from a first-party plugin you haven't installed, validation fails with `ECP_PLUGINS_MISSING` and the exact install command.

## Install

```bash
ecp plugins install jsonata                 # first-party short name
ecp plugins install @acme/text-stats        # any npm package
ecp plugins install ./acme-text-stats-1.0.0.tgz
```

Short names resolve to `@executioncontrolprotocol/<name>`. Installing an existing plugin is a no-op unless you pass `--force`. After every install, update, link, or removal, the host restarts automatically to load the change, usually within a second or two. In scripts, run `ecp host stop` right after installing: it returns once the old host has exited, and the next command starts a fresh host that has the plugin.

Plugins run inside the host with your permissions. Install third-party plugins only from sources you trust. See [Security](/learn/security#plugins-run-with-your-permissions).

## Manage

| Command | Does |
| ------- | ---- |
| `ecp plugins` | List installed plugins with version, source (`core`, `user`, `link`), and manifest status |
| `ecp plugins link [path]` | Use a local plugin folder without publishing it |
| `ecp plugins uninstall <package>` | Remove a plugin (aliases: `remove`, `unlink`) |
| `ecp plugins update` | Update installed plugins |
| `ecp plugins reset` | Remove every installed and linked plugin; the core plugin stays |
| `ecp plugins inspect <package>` | Show where a plugin is installed and its package details |

Plugins install under `$ECP_HOME/plugins`, so each `ECP_HOME` has its own set.

## When a plugin doesn't load

`ecp plugins` shows `ok` in the manifest column, or the first problem. A plugin whose manifest is missing, stale, or invalid stays installed but its capabilities aren't registered; the host still starts. See every issue with:

```bash
ecp retrieve --type plugin --id <package>
```

The usual fix for a plugin you are building is to rebuild it, which regenerates its manifest with `ecp-plugin-manifest`.

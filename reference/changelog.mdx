## Realignment

ECP (Execution Control Protocol) was rebuilt around a local host and a JSON execution manifest. This release breaks compatibility with the 0.5x field test; there is no migration shim.

### New

- **Execution manifest v2.** Executions are JSON (`*.ecp.json`, `version: "2.0"`) with step, branch, loop, and parallel nodes. One `expr` field controls routing.
- **Loops.** One `loop` node with `while`, `for`, and `forEach` modes. `forEach` runs items on isolated state copies with `concurrency` and `onError`.
- **Transforms.** `core.transform` (sandboxed JavaScript) and the optional `jsonata.transform` reshape data as typed steps with their own `accepts` and `returns`.
- **Layered validation.** Structure, inputs, semantics, data flow, and run input, with JSON Pointer paths, suggestions, and available state paths.
- **Three operations.** `retrieve`, `execute`, and `commit`, identical across the CLI, MCP, HTTP, and the in-process API.
- **Background host.** Starts on demand, restarts on plugin changes, stops when idle, and resumes interrupted runs.
- **MCP relay.** `ecp mcp start` exposes exactly three tools.
- **The App.** `ecp app` shows a live, hot-reloading graph with validation, runs, and run replay.
- **Configs and secrets.** Config objects with `$secret` references; values in the OS keychain.
- **Files.** `FileRef` references, a host file service for plugins, uniform capture of output files into run artifacts, and explicit publish steps.
- **Plugin SDK.** `definePlugin` and `capability` with zod schemas, lazy handlers, and generated `ecp.manifest.json` and `ecp.schema.json`.

### Removed

- Fluent TypeScript workflow files (`*.ecp.ts`) and the requirements document
- Environments, `--env` overlays, and policies
- `ecp search`, `describe`, `validate`, `run`, `runs`, `init`, `invoke`; use `retrieve` and `execute`
- `ecp mcp serve`, per-capability MCP tools, and MCP resources; use `ecp mcp start`
- Plugin-generated CLI commands
- Run journals under `.ecp/runs`; runs now live under `$ECP_HOME/runs`

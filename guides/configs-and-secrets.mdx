---
title: "Configs and secrets"
description: "Give ECP (Execution Control Protocol) plugins their settings and credentials with config objects and OS keychain secrets, without ever putting a secret in an execution."
---

Plugins that call external services need settings (a model name, a storage account) and credentials (an API key). ECP (Execution Control Protocol) keeps both out of executions: settings live in **config objects**, and credentials are **secret references** whose values sit in your OS keychain.

## Config objects

A config object holds the settings for one plugin:

```json anthropic-default.json
{
  "schema": "@executioncontrolprotocol.config",
  "version": "1.0",
  "id": "anthropic/default",
  "plugin": "@executioncontrolprotocol/anthropic",
  "values": {
    "model": "claude-sonnet-4-5",
    "apiKey": { "$secret": "anthropic.apiKey" }
  }
}
```

- `id` is `<plugin-short>/<name>`, where `plugin-short` is the plugin id without its scope.
- `values` is checked against the plugin's config schema. Read it with `ecp retrieve --type capability --id <capability>` (the `configSchema` field).
- `{ "$secret": "<key>" }` is resolved from the secrets store at run time.
- `{ "$env": "<NAME>" }` is resolved from the host's environment variables.

## Store a secret

Secret values are written only from your terminal:

```bash
ecp config secrets set anthropic.apiKey
```

The command reads the value from a hidden prompt or stdin and never echoes it. It is stored in your OS keychain (macOS Keychain, Windows Credential Manager, or the Secret Service on Linux).

```bash
ecp config secrets list
```

```text
key               source
anthropic.apiKey  keychain
```

Remove one with `ecp config secrets unset <key>`.

### CI and containers

Where there is no keychain, set an environment variable instead. The name is `ECP_SECRET_` plus the key, upper-cased, with every non-alphanumeric character replaced by `_`:

```bash
export ECP_SECRET_ANTHROPIC_APIKEY="..."
```

If both exist, the keychain value wins.

## Commit the config

```bash
ecp commit --type config --action create --object @anthropic-default.json
ecp retrieve --type config
```

The plugin must be installed, or the commit fails with `ECP_PLUGINS_MISSING`. To change a config, update it with the version you last read:

```bash
ecp commit --type config --action update --id anthropic/default --object @anthropic-default.json --if-version 1
```

## Use a config from a step

A step uses `<plugin-short>/default` automatically when it exists. Name another one with `config`:

```json
{ "id": "draft", "uses": "@executioncontrolprotocol/anthropic.generate", "config": "anthropic/drafting", "input": { "prompt": "..." }, "as": "draft" }
```

At run time, for each step the host loads the config, resolves secrets and environment references, validates the result against the plugin's schema, and passes it to the capability. The step record stores only the config's id and version.

## What happens when something is missing

| Situation | Code | When |
| --------- | ---- | ---- |
| The step names a config that doesn't exist | `ECP_CONFIG_UNKNOWN` | Validation |
| The config doesn't match the plugin's schema | `ECP_CONFIG_INVALID` | Validation or run time |
| A `$secret` has no value | `ECP_SECRET_MISSING` | Run time; the message names the key and the `ecp config secrets set` command |
| An execution contains `$secret` or `$env` | `ECP_MANIFEST_INVALID` | Validation, with a suggestion to move it into a config |

Agents should stop at `ECP_SECRET_MISSING` and ask you to set the secret. They can't set it through MCP.

## Redaction

During a run, every secret value the host resolved is replaced with `[redacted]` before anything is written to state, step records, events, logs, or responses, including when a plugin returns the value in its output.

# Environments

An environment is a **host** plus the plugins it has installed. Node and browser are hosts. The CLI process host is Node plus whatever you installed with `ecp plugins install`.

Machine settings live in optional `config.ecp.ts`. That file does not define the catalog. `ecp environments describe` lists the live host. The App Config tab shows the config file itself.

## Compose

Programmatic hosts still use `environment(id).with([...])`. The user config file does not:

```ts
import { config, extension, policy, secrets } from "@executioncontrolprotocol/core"

export default config().with([
  extension("@executioncontrolprotocol/anthropic").with({
    apiKey: secrets("anthropic/api-key"),
    defaultModel: "claude-sonnet-5-5",
  }),
  policy("@executioncontrolprotocol/budget").with({ maxCostUsd: 5 }),
])
```

`.supports(environmentId, range?)` on a definition restricts it to a host. Browser-only plugins fail on Node with `ECP_ENVIRONMENT_UNSUPPORTED`.

## Layering

1. Host always-on policies (for example registry-control on the CLI).
2. Installed plugins (the catalog).
3. Optional `config.ecp.ts` / `--config` settings merged onto matching plugins.
4. Workflow-file `.with([...])` / inferred requirements.

Config bindings for plugins that are not installed fail with `ECP_PLUGINS_MISSING`. They do not hide the rest of the catalog.

## CLI

```bash
ecp run brief.ecp.ts
ecp environments describe
ecp config init
ecp config edit
ecp environments export --format package-json
```

The default config file lives in `~/.ecp/config/config.ecp.ts` (`ECP_CONFIG_DIR` / `XDG_CONFIG_HOME` override that). `ecp config edit` prints the resolved path, scaffolds the file if it is missing, then opens `$VISUAL` or `$EDITOR`.

Omit `--config` unless you need a specific file. The default `config.ecp.ts` is enough when it exists.

`env.init()` returns an **Ecp**. Call `run`, `validate`, `describe`, `search`, `invoke`, `encode`, `decode`, `patch`, and `terminate` on that instance.

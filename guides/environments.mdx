# Environments

An environment is a **host** plus the plugins and policies it loads. Node and browser are hosts. The CLI process host is Node plus whatever you installed with `ecp plugins install`.

## Compose

```ts
import { environment, extension, NODE_ENVIRONMENT_ID } from "@executioncontrolprotocol/node"
import jsonataExtension from "@executioncontrolprotocol/plugin-jsonata"

export default environment(NODE_ENVIRONMENT_ID, "local").with([
  extension(jsonataExtension),
])
```

`.supports(environmentId, range?)` on a definition restricts it to a host. Browser-only plugins fail on Node with `ECP_ENVIRONMENT_UNSUPPORTED`.

## Layering

1. Host always-on policies (for example registry-control on the CLI).
2. Installed plugins.
3. Optional `--env <file>` overlay (`environment(id).with([...])`).
4. Workflow-file `.with([...])` / inferred requirements.

The overlay is extra bindings, not a required pair of `workflow.ts` + `environment.ts`.

## CLI

```bash
ecp run brief.ecp.ts
ecp run brief.ecp.ts --env ./local.env.ts
ecp environments describe
ecp environments describe --env ./local.env.ts
ecp environments init
ecp environments edit
ecp environments export --format package-json
```

The default environment file lives in `~/.ecp/config/environment.ecp.ts` (`ECP_CONFIG_DIR` / `XDG_CONFIG_HOME` override that). `environments edit` prints the resolved path, scaffolds the file if it is missing, then opens `$VISUAL` or `$EDITOR`.

Omit `--env` unless you need extra host bindings (secrets providers, extra policies).

`env.init()` returns an **Ecp**. Call `run`, `validate`, `describe`, `search`, `invoke`, `encode`, `decode`, `patch`, and `terminate` on that instance.

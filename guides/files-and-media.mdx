# Files and media

ECP (Execution Control Protocol) moves binaries as **file references**, not as inlined bytes in the workflow graph.

## FileRef

A `FileRef` is `{ uri, mediaType?, name? }`. Steps accept refs in inputs and return refs in outputs. The host resolves `uri` at run time.

Do not embed secret paths or credentials in the ref. Use `secrets("key")` for credentials; pass the ref as data.

## Resolve and write

Plugin code uses host helpers:

- `resolveFile(ref)` — read bytes (and metadata) for a `FileRef`
- `writeMediaArtifact(bytes, { mediaType, name })` — persist output and return a new `FileRef`

These live on the execution context. Plugins never import Node or browser hosts.

## Storage plugins

Upload and download go through plugins, not a core storage package. First-party example: `@executioncontrolprotocol/plugin-azure-blob-storage` (`ecp plugins install azure-blob-storage`). Image bytes go through `@executioncontrolprotocol/plugin-image-sharp` and generative inference through `@executioncontrolprotocol/plugin-fal` or Adobe Firefly Services.

## Journals

Run artifacts and events live under `.ecp/runs/<runId>/` (override with `ECP_RUNS_DIR`). The journal records step outputs, including file refs. See [Journal](/reference/journal).
